# みんなのクリスマスツリー 🎄

オンラインでクリスマスツリーを飾り付けできるサイトです。
ログインした人ごとに自分のツリーを作れて、シェアリンクでお友達に見せられます。

- 公開先（予定）: https://tr3131kami.github.io/xmas/
- リポジトリ名: `xmas`

## できること

- 飾り（星・ボール・ベル・キャンディケーン・リボン・雪・プレゼントなど）を選んで、ツリーをタップして置く
- 置いた飾りはドラッグで移動、軽くタップすると削除、まとめて消すボタンもあります
- ログインした人だけが自分のツリーを作成・編集できます
- シェアリンクを開いた人は、ログインしていなくてもそのツリーを **見るだけ** できます

## シェアリンク

形式: `/?q=<シェアID>`

- シェアIDはツリーの持ち主が自分で決めます
- 使える文字: 半角の英数字と `-` と `_`、3〜30文字
- 保存するときに設定・変更できます。すでに他の人が使っているIDは使えません
- 自分のツリーの一覧は、ログインするとページ下の「わたしのツリー」に出ます

## 設定 (CONFIG)

`index.html` の `<script type="module">` の先頭に CONFIG ブロックがあります。

```js
const MICROCMS_SERVICE_DOMAIN = 'projec5'; // サービスドメイン
const MICROCMS_ENDPOINT = 'xmas';          // エンドポイントID
const MICROCMS_API_KEY = '';               // ← microCMS の APIキーをここに入れる
```

- `MICROCMS_API_KEY` が空の間は **ローカルテストモード** で動きます。
  保存先はその端末のブラウザの localStorage (`xmas_trees_v1`) になり、
  ページ上にも「ローカルテストモードです」と表示されます。
  この状態でも、飾り付け・保存・シェアID・自分のツリー一覧など全機能をテストできます
  （ただし保存はその端末・そのブラウザの中だけです）。
- APIキーを入れると microCMS モードになり、取得に失敗したときも自動でローカル保存に切り替わります。

> 注意: GitHub Pages のような静的サイトでは、APIキーはページを見る人にも見える場所に置かれます。
> microCMS 側ではこの用途専用のキーを作り、権限はこのエンドポイントの GET / POST / PUT だけに絞ってください。

## microCMS で作るもの（ユーザー側の作業）

microCMS（サービスドメイン: `projec5`）で、API を1つ作ってください。

- API名 / エンドポイントID: `xmas`
- 型: リスト形式（コンテンツ一覧）

### フィールド

| フィールドID | 表示名（目安） | 型 |
| --- | --- | --- |
| `shareId` | シェアID | テキストフィールド |
| `ownerId` | 持ち主ID | テキストフィールド |
| `ownerName` | 持ち主の名前 | テキストフィールド |
| `title` | タイトル | テキストフィールド |
| `data` | 飾りデータ | テキストエリア（またはテキストフィールド） |

### 保存されるデータ

1件 = 1本のツリーです。

- `shareId`: シェアID
- `ownerId`: ログイン方法つきの持ち主ID（例 `sls:suzunokana` / `fb:<uid>` / `friend-kana`）
- `ownerName`: 表示名
- `title`: ツリーのタイトル
- `data`: 飾りの JSON 文字列。`[{"type":"star","x":50,"y":12}, ...]` の形で、
  `x` / `y` はツリーエリア内の位置をパーセント（0〜100）で表します

サイト側の動き:

- シェアIDでツリーを開く: `GET` に `filters[shareId][equals]<id>` を付けて検索
- 保存: まずシェアIDで検索し、自分の既存レコードがあれば `PUT` で更新、なければ `POST` で新規作成
- 自分のツリー一覧: `filters[ownerId][equals]<ownerId>` で検索

### APIキーの権限

- 上の `xmas` エンドポイントに対して **GET と POST（と PUT）** ができるキーが必要です
- 作ったキーを `index.html` の `MICROCMS_API_KEY` に貼ると、microCMS モードで動き始めます

## ログインについて

ログイン方法は4つです（ホームページ yt-hp と同じ仕組みを流用しています）。

1. **Scratch (ScratchLoginSystem / SLS)**
   - `https://tr3131kami.github.io/ScratchLoginSystem/scratch-login.js` を読み込みます
   - 認証プロジェクトID: `1436331790`
   - ログインしたユーザー名は localStorage の `sls_user` に保存されます
   - ownerId は `sls:<ユーザー名>` になります
2. **Google / 3. GitHub**
   - Firebase Auth（プロジェクト: `tororo-hp`）を使います。設定は yt-hp の `index.html` と同じものです
   - ownerId は `fb:<uid>` になります
4. **メールアドレス + パスワード**
   - 通常のアカウントは Firebase Auth のメール/パスワードログインです（新規登録ボタンもあります）
   - **お友達用かんたんログイン（サイト内ログイン）**:
     メールアドレス `a@kana.com` / パスワード `aiueo` でログインできます。
     表示名は「かな（友達用）」、ownerId は `friend-kana` で固定です。
     これは **Firebase には登録しません**。
     Firebase Auth はパスワードが6文字以上でないと使えないため、
     この短いパスワードのまま使えるように、サイト内だけで判定する特別なログインにしています。
     そのため、このログインは端末のブラウザ内にだけ保存され、他の端末とは共有されません。

編集できるのは持ち主だけです。他の人のツリーをシェアリンクで開いた場合は、
ログインしていても見るだけ（編集不可）になります。

## ローカルで確認する方法

`index.html` をブラウザで開くだけで、ローカルテストモードで全機能を試せます。

- ログイン: お友達用かんたんログイン（上記）を使うと、外部サービスなしで保存まで試せます
- 保存したツリーは同じブラウザの localStorage に入るので、`?q=<決めたシェアID>` を開き直すと確認できます
